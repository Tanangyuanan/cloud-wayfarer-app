# 阿镜世界数据维护说明

这里不是前台数据产品，而是阿镜在云游四方中感知、选择、理解和记忆贵州的底层资产。

## 目录内容

- `data-sources.json`：公开 API、现有工具、候选来源和需要合作的数据目录；
- `inference-rules.json`：由直接观测得到事件、身体影响和概率判断的规则；
- `world-snapshot.schema.json`：单次阿镜世界快照的数据契约；
- `server/public-world-tools.js`：统一接入公开地形、历史、水文、生物、地震、火点、轨道和航空接口；
- `server/world-data.js`：把当前位置、公开观测和推演结果组合成运行时快照。

## 运行链路

```text
数据源
→ 带时间和来源的 observation
→ 事件检测或推演 rule
→ world event
→ 阿镜感知边界与注意排序
→ 身体、行动、内容或记忆变化
```

`journey.events` 记录阿镜出发、抵达、停留、装订等产品事件；`environment.world.events` 记录贵州现实世界事件。两者不能混用。

## 证据口径

| 口径 | 含义 | 阿镜可以怎样使用 |
|---|---|---|
| `direct` | 内部时钟、路线、已确认位置或直接传感器 | 可作为事实 |
| `modelled_observation` | 天气、空气、全球水文等模型结果 | 可支持身体和决策，但要保留来源尺度 |
| `reported_observation` | 物种或人工上报 | 可以说“有人记录/上报”，不能改写成亲历 |
| `calculated` | 日出窗口、单位换算、历史频率 | 可以表达计算结果和适用范围 |
| `derived` | 湿滑、云海、花期、菌子等推演 | 只能作为概率、注意或行动线索 |

## 新增数据源的门槛

每个来源必须填写：

1. 数据改变阿镜的哪一种状态；
2. 获取方式、授权和署名要求；
3. 时间、空间分辨率和正常更新频率；
4. 失效时间、超时和降级方式；
5. 是否能支持第一人称亲历；
6. 已知误差、隐私和安全边界；
7. 官方文档与最近核验日期；同批核验可使用目录的 `meta.checkedAt`，单独复核时写在来源自身。

公开页面能看见数据，不等于存在可依赖的公开 API；内部系统有实时数据，也不等于获得了再使用和再发布权。

## 新增推演规则的门槛

每条规则必须包含输入字段、算法或阈值、输出、置信度、影响范围和第一人称边界。规则发布后不静默修改：更新规则版本，新旧事件保留产生时使用的规则版本。

推演结果若不改变身体、注意、行动、理解、关系或记忆，不进入阿镜上下文。

## 维护节奏

- 每日：检查来源断流、延迟、异常值和事件过期；
- 每周：抽检阿镜是否越过亲历边界，复盘哪些事件真正改变了行动；
- 每月：核验授权与官方文档，更新覆盖、阈值和历史基线；
- 每季：清理长期无价值数据，评审新增领域和合作需求。

## 当前首批运行能力

已经进入 `observe_environment`：

- 当地时间、季节、位置；
- Open-Meteo 当前天气、云量、能见度、阵风、气压和模型高程；
- Open-Meteo 空气质量；
- Open-Meteo 90 米高程、历史同期基线和 GloFAS 全球河流模型；
- GBIF 与 iNaturalist 附近物种记录；
- USGS 近七天地震事件；
- NASA FIRMS 卫星热异常（配置免费 `NASA_FIRMS_MAP_KEY` 后运行）；
- CelesTrak 轨道要素及阿镜所在地未来 24 小时 ISS 可见过境计算；
- OpenSky 附近航空器状态（默认匿名访问，也支持 OAuth）；
- 降水、有雾、低能见度、高湿身体负担、湿滑可能、日出日落光线窗口、空气质量负担等事件。

当前目录中的公开 API 已全部完成代码接入。贵州精细水文、景区客流、桥梁、FAST、博物馆、农业与发酵数据仍需要合作或认证上报。

公开接口默认并行获取并独立降级。缓存周期按数据变化速度设置：航空 10 分钟、地震 15 分钟、火点 30 分钟、生物 1—6 小时、河流 6 小时、历史基线 7 天、高程 30 天。上游失败不会阻塞其他来源。

运行 `npm run data:smoke -- fanjingshan` 可对指定地点进行真实接口冒烟检查；输出只包含每个来源的可用状态和原因，不打印密钥或原始敏感配置。
